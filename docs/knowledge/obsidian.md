# Obsidian 使用教程

Obsidian 是一款本地优先的 Markdown 笔记工具。它把笔记保存在电脑或手机上的普通文件夹里，每篇笔记都是一个 `.md` 文件，适合搭建个人知识库、学习笔记、项目资料库和长期写作系统。

这篇教程按「先能用起来，再逐步增强」的顺序组织。新手可以照着前几节完成第一套知识库；已经用过 Obsidian 的用户，可以重点看属性、模板、Bases、插件和备份部分。

## 一页看懂

| 概念 | 说明 | 新手怎么用 |
|------|------|------------|
| Vault | 一个知识库文件夹 | 为个人学习、工作项目分别创建 Vault |
| Note | 一篇 Markdown 笔记 | 用标题、列表、任务清单记录内容 |
| Link | 笔记之间的链接 | 用 `[[笔记名]]` 连接相关概念 |
| Backlinks | 反向链接 | 查看哪些笔记提到了当前笔记 |
| Tags | 标签 | 标记主题或状态，例如 `#待读`、`#项目/进行中` |
| Properties | 笔记属性 | 用 `status`、`type`、`created` 等字段管理信息 |
| Canvas | 白板画布 | 视觉化整理项目路线、课程大纲和文章结构 |
| Bases | 数据视图 | 把带属性的笔记展示成表格、列表或卡片视图 |
| Plugins | 插件 | 先用核心插件，确有需求再安装社区插件 |

## 适合谁使用

- 想把学习资料、项目记录和灵感统一管理的人
- 习惯 Markdown，或者愿意学习简单 Markdown 语法的人
- 希望笔记数据保存在本地，方便备份、迁移和版本管理的人
- 想用双向链接把零散知识连接起来的人
- 想把 AI 对话、阅读摘录、会议记录沉淀成长期知识库的人

::: tip AI 联动工作流
如果你想把 Obsidian 和 AI 工具结合使用，可以按任务选择：[Obsidian Claudian](/knowledge/obsidian-claudian) 适合在 Vault 内直接调用 Claude、Codex、OpenCode；[Obsidian + Codex](/knowledge/obsidian-codex) 适合把项目上下文转成可执行开发任务；[Obsidian + Claude](/knowledge/obsidian-claude) 适合长文档总结、需求拆解、资料整理和文档复审。
:::

## 不太适合的场景

- 需要多人实时协作文档，可以优先考虑 Google Docs、Notion、飞书文档
- 只想做简单待办清单，可以优先考虑系统备忘录或 Todo 应用
- 不愿意维护文件、同步和备份，Obsidian 的本地优先特性可能会增加心智负担

## 安装与创建 Vault

1. 打开 [Obsidian 官网下载页](https://obsidian.md/download)
2. 选择 macOS、Windows、Linux、iOS 或 Android 对应版本
3. 安装完成后打开 Obsidian
4. 第一次启动时选择「Create new vault」
5. 设置 Vault 名称和保存位置

::: tip Vault 是什么？
Vault 可以理解为一个知识库文件夹。Obsidian 会把笔记、附件和配置保存在这个文件夹中。建议不同用途分开管理，例如「个人知识库」「工作项目」「课程学习」。
:::

::: warning 不要套娃创建 Vault
不要在一个 Vault 里面再创建另一个 Vault。内部链接按当前 Vault 解析，嵌套 Vault 容易造成链接、插件和配置混乱。
:::

## 建议先做的设置

进入 Settings 后，先完成这些基础设置：

| 设置项 | 建议 |
|--------|------|
| Files and links | 新建笔记默认放到 `00-Inbox` 或当前文件夹 |
| New link format | 选择 Obsidian 默认的 Wiki links，写起来更顺手 |
| Attachment folder path | 设置为 `Attachments`，避免图片散落各处 |
| Always update internal links | 开启，重命名笔记时自动更新内部链接 |
| Core plugins | 开启 Daily notes、Templates、Backlinks、Outgoing links、Canvas、Bases |
| Hotkeys | 给常用命令设置快捷键，例如插入模板、打开日记、移动文件 |

::: tip 配置也在本地
Vault 中的 `.obsidian` 文件夹保存主题、插件和设置。同步或备份 Vault 时，要决定是否把 `.obsidian` 一起同步。个人设备之间通常可以同步；多人共享 Vault 时要谨慎。
:::

## Markdown 基础

Obsidian 默认使用 Markdown。先掌握这些就够日常使用：

| 用法 | 写法 | 效果 |
|------|------|------|
| 标题 | `# 标题` | 一级标题 |
| 二级标题 | `## 标题` | 二级标题 |
| 加粗 | `**重点**` | **重点** |
| 无序列表 | `- 内容` | 列表项 |
| 有序列表 | `1. 内容` | 编号列表 |
| 任务 | `- [ ] 待办` | 待办事项 |
| 引用 | `> 说明` | 引用块 |
| 行内代码 | `` `code` `` | 行内代码 |
| 代码块 | ```` ```js ```` | 多行代码 |
| 分隔线 | `---` | 分隔内容 |

第一篇笔记可以这样写：

```markdown
# 我的第一篇笔记

今天开始使用 Obsidian。

## 记录内容

- 学到的概念
- 遇到的问题
- 后续要做的事

## 待办

- [ ] 创建目录结构
- [ ] 写一篇日记
- [ ] 学会使用双向链接
```

## 双向链接

在笔记中输入 `[[笔记名]]`，就可以链接到另一篇笔记：

```markdown
今天学习了 [[提示词工程]]，它和 [[ChatGPT]] 的使用效果关系很大。
```

如果目标笔记还不存在，点击这个链接就能直接创建新笔记。这个方式适合先记录想法，再逐步补全内容。

常用链接写法：

| 写法 | 用途 |
|------|------|
| `[[ChatGPT]]` | 链接到一篇笔记 |
| `[[ChatGPT#使用场景]]` | 链接到某个标题 |
| `[[ChatGPT|AI 对话助手]]` | 使用别名显示链接 |
| `![[图片.png]]` | 嵌入图片 |
| `![[会议记录]]` | 嵌入另一篇笔记内容 |

::: tip 链接原则
链接真正有复用价值的概念，不要把每个词都变成链接。好的链接应该能帮你在未来重新发现关系。
:::

## 标签与属性

标签适合表示主题和状态：

```markdown
#AI工具 #学习笔记 #项目/进行中
```

属性适合放结构化信息。它们写在笔记顶部：

```yaml
---
type: note
status: draft
created: 2026-06-05
tags:
  - 学习笔记
  - AI工具
source: https://example.com
---
```

常用属性建议：

| 属性 | 示例 | 用途 |
|------|------|------|
| `type` | `project`、`book`、`meeting` | 区分笔记类型 |
| `status` | `draft`、`active`、`done` | 管理状态 |
| `created` | `2026-06-05` | 创建日期 |
| `updated` | `2026-06-05` | 更新日期 |
| `source` | `https://...` | 原文来源 |
| `author` | `作者名` | 书籍、文章、论文作者 |
| `tags` | `AI工具` | 主题标签 |

::: tip 标签和属性怎么选？
标签适合快速筛选主题或状态；属性适合做表格、列表、卡片等结构化视图。以后要用 Bases 或 Dataview 查询的内容，优先放进属性。
:::

## 推荐目录结构

新手可以先用一个简单结构，不要一开始设计太复杂：

```text
Obsidian Vault/
├── 00-Inbox/
├── 10-Projects/
├── 20-Areas/
├── 30-Resources/
├── 40-Archive/
├── Attachments/
└── Templates/
```

| 文件夹 | 用途 |
|--------|------|
| `00-Inbox` | 临时记录，还没整理的内容 |
| `10-Projects` | 有明确目标和截止时间的项目 |
| `20-Areas` | 长期维护的领域，例如工作、健康、学习 |
| `30-Resources` | 可复用资料，例如教程、文章摘录、概念笔记 |
| `40-Archive` | 已完成或暂时不用的内容 |
| `Attachments` | 图片、PDF、附件 |
| `Templates` | 笔记模板 |

这套结构接近 PARA 的思路：项目是短期目标，领域是长期责任，资源是可复用资料，归档是暂时不用但需要保留的内容。

## 笔记命名建议

| 类型 | 命名示例 | 说明 |
|------|----------|------|
| 概念笔记 | `提示词工程` | 用概念名，不要太长 |
| 项目笔记 | `项目 - AI 工具文档站` | 前缀方便聚合 |
| 日记 | `2026-06-05` | 使用固定日期格式 |
| 会议记录 | `会议 - 产品评审 - 2026-06-05` | 方便搜索和排序 |
| 读书笔记 | `读书 - 卡片笔记写作法` | 保留资料类型 |
| 资料摘录 | `资料 - Obsidian Bases 介绍` | 表明来源性质 |

## 常用核心功能

### 快速切换

按 `Cmd + O` 或 `Ctrl + O` 可以快速搜索并打开笔记。笔记变多后，这是最常用的入口。

### 命令面板

按 `Cmd + P` 或 `Ctrl + P` 打开命令面板，可以搜索 Obsidian 的各种命令，例如打开图谱、插入模板、切换主题、导出 PDF 等。

### 搜索

左侧 Search 可以按关键词搜索整个 Vault。常见用法：

```text
ChatGPT
tag:#AI工具
path:"10-Projects"
```

搜索适合找「我记得写过什么」；链接和反向链接适合找「这些内容之间有什么关系」。

### 反向链接

打开右侧 Backlinks 面板，可以看到哪些笔记链接到了当前笔记。它适合用来发现知识之间的关系。

### 出链

Outgoing links 面板可以看到当前笔记链接出去的内容，也能提示还没有创建的链接。

### 图谱视图

Graph view 会把笔记之间的链接展示成网络图。它适合查看知识库整体结构，但不要为了图谱好看而强行加链接。

### 日记

开启核心插件 Daily notes 后，可以每天生成一篇当天笔记。适合记录当天计划、会议纪要、学习总结和临时想法。

### 模板

开启核心插件 Templates 后，可以把常用格式保存为模板。建议把模板放进 `Templates` 文件夹，然后在设置中指定模板目录。

### Canvas

Canvas 适合做视觉化整理，比如课程大纲、项目路线图、文章结构和头脑风暴。你可以把笔记、图片、网页链接拖到画布上，用连线表达关系。

### Bases

Bases 可以把带属性的笔记整理成表格、列表或卡片视图。它适合做项目列表、阅读清单、课程资料库、插件清单等结构化管理。

一个适合 Bases 的项目笔记属性：

```yaml
---
type: project
status: active
owner: Steven
start: 2026-06-05
deadline: 2026-06-30
tags:
  - 项目
---
```

以后可以按 `type = project` 筛选出所有项目，再按 `status` 或 `deadline` 排序。

## 一个实用工作流

### 每天

1. 打开 Daily note
2. 记录今天要做的事
3. 把临时想法先丢进 `00-Inbox`
4. 遇到重要概念时，用 `[[概念名]]` 建立链接
5. 下班或睡前花 5 分钟补充当天总结

### 每周

1. 清理 `00-Inbox`
2. 把临时笔记移动到合适文件夹
3. 给重要笔记补充标签、属性和链接
4. 把项目进展更新到项目笔记
5. 归档已完成项目
6. 检查是否完成备份

### 每个项目

1. 在 `10-Projects` 创建项目笔记
2. 写清楚目标、背景、关键资料和任务清单
3. 把相关会议记录、代码链接、设计稿、文档资料都链接到项目笔记
4. 用属性标记 `status`、`start`、`deadline`
5. 项目结束后写复盘，再移动到 `40-Archive`

## 学习路线

### 第 1 天：先能写

- 创建 Vault
- 建立 `00-Inbox`、`Attachments`、`Templates`
- 写 3 篇笔记
- 学会标题、列表、任务清单、双向链接

### 第 1 周：形成习惯

- 每天写 Daily note
- 用 `[[链接]]` 连接概念
- 给笔记添加基础标签
- 每周清理一次 `00-Inbox`

### 第 2 周：结构化

- 给项目、阅读、会议笔记添加属性
- 建立项目模板、阅读模板、会议模板
- 用 Backlinks 和 Outgoing links 检查关系
- 尝试用 Canvas 整理一个项目或课程

### 第 1 个月：逐步增强

- 用 Bases 管理项目或阅读清单
- 只安装 1 到 3 个真正需要的社区插件
- 设计同步和备份策略
- 输出一篇文章、复盘或学习总结

## 社区插件

Obsidian 的社区插件很强，但新手不要一开始装太多。插件本质上是第三方代码，安装前要看维护状态、下载量、更新记录和权限说明。

常见插件方向：

| 需求 | 常见选择 | 说明 |
|------|----------|------|
| 任务管理 | Tasks | 查询、聚合和管理待办事项 |
| 数据查询 | Dataview | 按属性、标签、文件夹生成动态列表 |
| 日历入口 | Calendar | 配合 Daily notes 使用 |
| 绘图白板 | Excalidraw | 手绘图、流程图、视觉笔记 |
| 搜索增强 | Omnisearch | 更强的全文搜索体验 |
| 文献管理 | Zotero Integration | 把 Zotero 文献和摘录带入笔记 |
| Git 备份 | Obsidian Git | 适合熟悉 Git 的用户 |

::: warning 插件安全
社区插件不是必须项。安装前先备份 Vault；不要安装来源不明、长期不维护、权限说明不清楚的插件；出现卡顿或异常时，先进入安全模式禁用插件排查。
:::

## 同步和备份

Obsidian 的笔记是本地文件，因此备份很重要。常见方式：

| 方式 | 特点 | 注意事项 |
|------|------|----------|
| Obsidian Sync | 官方同步服务，适合多设备稳定同步 | 付费服务，体验最省心 |
| iCloud / OneDrive / Dropbox | 上手简单 | 容易出现同步延迟或冲突，移动端尤其要谨慎 |
| Git | 适合开发者，可保留历史版本 | 不适合不熟悉 Git 的新手 |
| 手动备份 | 定期复制 Vault 到硬盘或 NAS | 需要养成固定习惯 |

备份建议：

- 至少保留一份本地备份和一份云端备份
- 批量改名、安装插件、迁移同步方案前先备份
- 不要同时用多个同步工具同步同一个 Vault
- 重要附件也要一起备份，不要只备份 `.md` 文件

## 常见问题

### 笔记很多后找不到内容

先用搜索和快速切换；再逐步补标签、属性和 MOC 笔记。MOC 可以理解为主题索引页，例如「AI 工具索引」「读书笔记索引」。

### 文件夹、标签、链接到底用哪个

文件夹管理稳定归属，标签管理主题和状态，链接表达内容关系。三者不是替代关系，可以一起使用。

### 图谱很乱怎么办

图谱不是目标，笔记可用才是目标。可以用局部图谱看当前主题附近的关系，不必追求全局图谱好看。

### 插件太多导致卡顿

先禁用近期安装的插件，再逐个启用排查。长期不用的插件直接卸载。核心功能能解决的问题，不要优先靠插件。

### 多设备同步冲突怎么办

先停止继续编辑，备份当前 Vault，再比较冲突文件。之后尽量避免多个设备同时打开同一个 Vault 修改同一篇笔记。

## 新手常见误区

- **一开始就设计复杂分类**：先用简单目录，等笔记变多后再调整
- **只收藏不消化**：摘录之后要写自己的理解
- **链接太少**：重要概念之间至少建立基本链接
- **链接太多**：不要把每个词都变成链接，只链接真正有复用价值的概念
- **插件装太多**：先用核心功能，确定需求后再安装社区插件
- **忘记备份**：本地优先不等于天然安全，备份要成为习惯
- **只整理不输出**：知识库最终要服务写作、决策、复盘和行动
